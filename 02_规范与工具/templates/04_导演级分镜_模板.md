# G3 导演分镜与单镜试拍

从 [05 分镜 JSON 模板](05_单源分镜JSON_模板.json) 复制到 `shots/EXX_spec.json`，或者沿用现有镜头清单。从确认过的有声静帧粗剪选择待验证的相邻镜头。第一轮可取 2–4 镜、共 12–25 秒，镜号与长度由实际素材决定。先确认每镜要看清什么、从上一镜接什么、哪一帧或姿态可切给下一镜。

## 1. 填写镜头与生成参数

| 内容 | 填写位置与方法 |
| --- | --- |
| 制作目标与衔接 | `shot_goal` 写可在审片中判断的结果。`handoff_note` 写需要承接的姿态、视线方向、物件状态、动作点或声音。剪辑入出点记在时间线和审片记录里。 |
| 构图、人物与素材 | `camera_angle` 和 `first_frame_note` 负责构图和首帧交接。`characters` 登记人物、造型和在场方式，只有手入画也算 `on_screen`。`refs.scene_plate` 和 `refs.props` 是首帧制作资料。 |
| 生成设置 | 在界面或 API 参数中设置入口支持的模式、画幅、清晰度、时长、视频参考图与模型版本。`dur` 对应生成档位，可用 `cut_duration` 单独计划剪入时长，用 `video_model` 记录选定的视频模型。能使用随机种子时记录它。 |
| 主体、动作与声音 | `video_prompt` 写模型需要看到或听到的变化。用可见物件、屏幕方位或已确定的画外站位锚定视线。一项主要动作通常足够。动作可以停留，必要的运镜只写方向、速度和终点。 |
| 台词与外配 | `dialogue` 放已确认的原文。`audio_mode` 声明路线。外配登记 `audio_file`，按实测时长留气口。方法见 [07 音画与后期模板](07_音画与后期_模板.md)。 |

先运行 `audit_shots.py` 检查所选镜头，再用 `build_episode.py` 派生执行提示词。提交到视频工具时只复制执行文件里对应镜号的 `text` 代码块。把参考图挂在对应的真实参考槽，保留镜头目标、路径、版本、费用和验收说明作为制作记录。本地预检在正文超过净 240 字时提醒精简，标点计入，提交限制以入口为准。替换占位符并删掉本镜用不到的句子。

## 2. 视频提示词主体

选择一个视觉模板，再按下节拼接一段声音模板。尖括号内填写已在画面或生产输入中核实的信息。有些镜头只需一句可见动作。

### A · 单首帧

默认用一张已验收的正式首帧，挂 `refs.first_frame`。首帧负责造型、色调、光线、初始构图；正文写起始动作和变化，角色用普通称呼。

```text
<<景别和视点>>。<<主体>>从<<首帧上可见的姿态>>开始，<<看向具体锚点并完成主要动作>>，最后<<可见的停留状态>>。<<确有必要时填写单一视点移动或次要反应>>。
```

### A+ · 首尾双帧

入口明确支持同一任务的首尾两帧时，分别挂 `refs.first_frame`、`refs.last_frame`。两帧先人工确认是同一场地、人物、衣着、视线轴、同一物件和相容的动作状态。用正文解决两帧之间的路径或动作接点。

```text
从<<首帧的构图和起始姿态>>开始。<<主体沿可见的方向和路径完成主要动作>>，经过<<必要的接触点或空间锚点>>，停在<<与尾帧一致的构图和终态>>。
```

### B · 多参考图

单首帧试拍无法同时保住所需的身份和空间，且入口支持多图绑定时，选择最低必要数量的正式图。参考图至少有一张，上限遵循 G0 核实的入口能力；路径和别名填入 `refs.mode_b_refs`。使用入口实际分配或支持的引用方式。入口支持 `@` 别名时，正文沿用已声明别名，别名与紧跟的词之间加空格或标点。如果入口只支持逐槽上传，先确认每槽的来源和用途，同时为每张图登记制作别名。无法可靠绑定时回到 A。

```text
<<入口实际支持的人物引用>>，用于<<需要保持的人物或服装特征>>。<<入口实际支持的场景引用>>，用于<<需要保持的空间或光向>>。<<视点和空间方位>>。<<主体>>完成<<一项可见动作>>，最后<<可见终态>>。
```

白模和线稿用于规划或辅助生成正式首帧。视频任务使用本模式规定的正式图。实际入口的时长或挂载能力与当前方案不符时，先改方案和源 JSON，再派生本轮提示词。

## 3. 选一段声音写法

`sfx_only` 用在没有对白的镜头，`dialogue` 留空。声响没有明确动作来源时只写环境底声。

```text
全程无对白。<<同场环境底声>>，<<指定动作的同期声>>。无字幕。
```

`native` 用在入口支持原生对白、已实读能自然落入该镜的短句。把 `dialogue` 中已确认文字逐字放进提示词，包含原定停顿与标点。约 4 字/秒仅供起步估算，正式以试读和口型表现为准。实读时长超过可用区间时，计划更长的生成时长或改用外配，仍沿用已确认原句。

```text
<<说话主体>>在<<可见动作或停顿>>后用<<语气>>说：“<<已确认的原句>>”<<需要时写听者的可见反应>>。<<必要的同期声>>。无字幕。
```

`vo_lipsync` 用在需要固定音色、已录对白或后期控制口型的镜头。初次生视频的正文只管闭口表演，不含台词与引号。已确认的原句和音频单独登记。可见口型在后期对齐，无法稳定对齐时使用听者反应或动作细节覆盖。

```text
<<主体>>闭口完成<<无声表演或反应>>，<<停在可用于后期接点的姿态>>。<<必要的环境底声>>。无字幕。
```

## 4. 下载、初选和重试

1. 按实际入口查看生成参数与挂载预览。扣费生成先按本轮批次报价和授权执行。任务提交后记录实际任务号，状态不明先查该任务。
2. 下载后存版本化候选。逐镜检查主动作和接点实际存在、身份和服装稳定、手与关键道具接触可信；有原生对白时逐字听校。截取计划使用的区间，暂过的候选进 G4 连放，同一镜仍保留其它版本供比较。
3. 如需重试，用以下模板写 `RUNLOG.md`。可先尝试调整一个动作措辞、替换一张脸部参考或减小一次视点移动。复制原设置，只改变记录里的变量，保证至少能判断这一项是否有帮助。同一缺陷重试两次仍无改善，或达到本轮预算，暂停问题镜，带时间码回到粗剪、资产或音频所在环节定位。

```text
镜号 / 候选版本 / 生成任务号
实际模型 / 生成档位 / 参考版本 / 费用
故障时间码与能观察到的现象
这一轮只改的变量
预期会出现的画面或声音变化
实测变化 / 是否保留 / 回到哪个工序
```
